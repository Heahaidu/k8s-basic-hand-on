# cAdvisor Missing `container` and `image` Labels on Kubernetes v1.35

## Symptoms

When scraping metrics from `/metrics/cadvisor` via Prometheus, all metrics appear as:

```
container_cpu_usage_seconds_total{container="", image="", namespace="default", pod="nginx-xxx"} 0.5
container_memory_working_set_bytes{container="", image="", ...} 104857600
```

The `container` and `image` labels are empty (`""`), causing Prometheus alerting rules, Grafana dashboards, and recording rules to break or return no data.

---

## Root Cause

### Architecture Breakdown

The issue occurs when Kubernetes uses **cri-dockerd** as the container runtime — commonly the default in Minikube.

```
┌─────────────────────────────────────────────────────────────┐
│  kubelet  ──→  cri-dockerd.sock  ──→  Docker daemon         │
│                (CRI interface)        (creates containers)   │
│                                                              │
│  cAdvisor ──→  docker.sock       ──→  Docker daemon          │
│                (Docker API)           "No such container" ❌ │
└─────────────────────────────────────────────────────────────┘
```

**Step by step:**

1. kubelet creates containers through **cri-dockerd** (a CRI shim). Container IDs are generated by cri-dockerd.
2. cAdvisor (embedded inside kubelet) independently connects to **docker.sock** to query container metadata.
3. Docker daemon does not recognize the container IDs generated by cri-dockerd → returns `"No such container"`.
4. cAdvisor cannot retrieve container name or image → labels are left empty.

### Typical Log Errors

```
kubelet[2170]: "DeleteContainer returned error" err="failed to get container status:
rpc error: code = Unknown desc = Error response from daemon: No such container: abc123..."

cadvisor_stats_provider.go:569] "Partial failure issuing cadvisor.ContainerInfoV2"
err="partial failures: [\"/kubepods/besteffort/pod...\": RecentStats: unable to find data in memory cache]"
```

### Why containerd/cri-o Do Not Have This Problem

cAdvisor has built-in **factories** for each supported runtime, detected in priority order:

| Runtime    | Socket Path                        | cAdvisor Support  |
|------------|------------------------------------|-------------------|
| containerd | `/run/containerd/containerd.sock`  | ✅ Native          |
| cri-o      | `/run/crio/crio.sock`              | ✅ Native          |
| docker     | `/var/run/docker.sock`             | ⚠️ Docker API only |
| cri-dockerd| `/var/run/cri-dockerd.sock`        | ❌ Not detected    |

With **containerd** and **cri-o**, kubelet and cAdvisor share the **same socket** — container IDs match exactly and full metadata is available.

```
┌─────────────────────────────────────────────────────────────┐
│  kubelet  ──→  containerd.sock  ──→  containerd runtime      │
│                                                              │
│  cAdvisor ──→  containerd.sock  ──→  containerd runtime      │
│                (same socket!)         full metadata ✅       │
└─────────────────────────────────────────────────────────────┘
```

### Historical Context

| Version | Change |
|---|---|
| Kubernetes 1.20 | Docker runtime deprecated |
| Kubernetes 1.24 | Dockershim removed from kubelet. cri-dockerd released as an external shim |
| Kubernetes 1.35 | cri-dockerd still works for scheduling, but cAdvisor metadata enrichment is broken |

## How to Confirm the Issue

```bash
# Check which container runtime is in use
kubectl get nodes -o jsonpath='{range .items[*]}{.metadata.name}{"\t"}{.status.nodeInfo.containerRuntimeVersion}{"\n"}{end}'

# Check if metrics have labels
kubectl get --raw /api/v1/nodes/<node-name>/proxy/metrics/cadvisor | \
  grep 'container_cpu_usage_seconds_total' | \
  grep -v 'container=""' | \
  grep -v 'container="POD"' | \
  head -5

# No output = labels are missing
```

```bash
# Check kubelet config
cat /var/lib/kubelet/config.yaml | grep containerRuntimeEndpoint
# containerRuntimeEndpoint: unix:///var/run/cri-dockerd.sock  ← root cause
```

## Fix

### Permanent Fix: Switch Container Runtime to containerd

This is the only real solution. cri-dockerd with cAdvisor is a fundamentally broken combination in Kubernetes 1.35.

#### Minikube (Docker driver)

```bash
# Delete the existing cluster
minikube delete

# Recreate with containerd
minikube start \
  --kubernetes-version=v1.35.0 \
  --container-runtime=containerd \
  --driver=docker
```

#### Minikube (Hyper-V driver)

```bash
minikube delete

minikube start \
  --kubernetes-version=v1.35.0 \
  --container-runtime=containerd \
  --driver=hyperv
```

#### kubeadm clusters

Update `/var/lib/kubelet/config.yaml`:

```yaml
containerRuntimeEndpoint: "unix:///run/containerd/containerd.sock"
```

Ensure containerd is installed and running:

```bash
systemctl status containerd
systemctl enable --now containerd
```

Restart kubelet:

```bash
systemctl restart kubelet
```

#### Verify the Fix

```bash
kubectl get --raw /api/v1/nodes/minikube/proxy/metrics/cadvisor | \
  grep 'container_cpu_usage_seconds_total' | \
  grep -v 'container=""' | \
  grep -v 'container="POD"' | \
  head -5
```

Expected output:

```
container_cpu_usage_seconds_total{container="coredns",image="registry.k8s.io/coredns/coredns:v1.12.0",namespace="kube-system",pod="coredns-xxx",...} 1.234
```

---

### Temporary Workaround (Not Recommended)

If switching the runtime is not immediately possible, use Prometheus relabeling to join with `kube-state-metrics`:

```promql
# Recover image info by joining with kube-state-metrics
container_cpu_usage_seconds_total
* on(namespace, pod, container)
group_left(image)
kube_pod_container_info
```

Or drop metrics with empty container labels in the scrape config:

```yaml
# prometheus.yml
metric_relabel_configs:
  - source_labels: [container]
    regex: ".+"   # Only keep metrics with a non-empty container label
    action: keep
```

> ⚠️ This workaround hides the problem rather than fixing it. Some node-level and pod-level aggregate metrics will be dropped as a side effect.

## Installing kube-prometheus-stack

After fixing the runtime, install the Prometheus stack:

```bash
helm repo add prometheus-community https://prometheus-community.github.io/helm-charts
helm repo update

# Install with CRDs (automatic)
helm install prometheus prometheus-community/kube-prometheus-stack \
  --namespace prometheus \
  --create-namespace \
  --timeout 10m \
  --wait
```

If you encounter a CRD error (`no matches for kind "ServiceMonitor"`):

```bash
# Manually install CRDs first
helm pull prometheus-community/kube-prometheus-stack --untar
kubectl apply --server-side -f kube-prometheus-stack/charts/crds/crds/

# Then install the chart without re-applying CRDs
helm install prometheus prometheus-community/kube-prometheus-stack \
  --namespace prometheus \
  --skip-crds
```

## Summary

| | cri-dockerd | containerd | cri-o |
|---|---|---|---|
| cAdvisor detection | ❌ | ✅ | ✅ |
| `container` label | ❌ empty | ✅ populated | ✅ populated |
| `image` label | ❌ empty | ✅ populated | ✅ populated |
| Kubernetes 1.35 support | ⚠️ partial | ✅ full | ✅ full |

**Bottom line:** Always use `--container-runtime=containerd` or `--container-runtime=cri-o` when provisioning a cluster to ensure cAdvisor works correctly with Prometheus.
